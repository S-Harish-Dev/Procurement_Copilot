# ADR-13: Observability: OpenTelemetry traces, Prometheus metrics, generated Grafana dashboards

- Status: accepted (2026-10-30)

## Decision
- Traces: OpenTelemetry 0.33 in Rust and Python (W3C `traceparent` across gRPC) to `otel-lgtm` (Tempo, Loki)
  in compose. Attributes carry versions, tier, cache layer, gate counts, never raw text.
- Metrics: the gateway exposes Prometheus pull metrics on :9464 (`metrics-exporter-prometheus`, explicit latency
  buckets so p95 is computable). A dedicated Prometheus 3.15.1 scrapes it (native stack and a compose service):
  otel-lgtm's Prometheus only receives OTLP pushes. Cost counters are integer micro-dollars
  (`llm_cost_usd_micros_total`, `jev_cost_usd_micros_total`).
- Known label sets are pre-registered at zero at startup: `increase()` cannot see a counter's first
  increment when the series appears at that moment (found when Insights showed `requests = null`).
- Dashboards: 5 generated by `infra/grafana/build_dashboards.py` (`make dashboards`): `pc-overview`,
  `pc-llm-cost`, `pc-retrieval`, `pc-security`, `pc-dependencies`; one colour per entity, shared with the web UI.
  Provisioned read-only with datasource uid `gateway-prom`; verified on native Grafana 13.3.0.
- Alerts (`infra/prometheus/alerts.yml`, promtool-checked): GuardBlockSpike, JevDegraded, ChatLatencySLO,
  LlmErrorRate, DependencyDown, ClassifierSkipped.
- In-app: `/admin/metrics/overview` runs PromQL server-side, so Insights and Grafana never disagree;
  `/admin/traces` serves an in-memory ring of the last 1,000 chat requests (stage spans with real offsets) for
  hosts without Tempo.

## Why
One source of truth for numbers (Prometheus) across Grafana, Insights and the load-test analysis; traces for
the "why was this slow/blocked" question; generated dashboards keep five boards consistent.

## Limits
Compose mounts the provisioning into otel-lgtm at assumed paths (unverified until the first `make up`). The native
stack has no Tempo, so `trace_id` and the Grafana link are empty there. The trace ring is per process and lost on restart.

## Alternatives rejected
- *OTLP-push metrics only*: would need the gateway to switch exporters; the pull endpoint is also what k6 runs read.
- *Hand-edited dashboard JSON*: drifts; per-entity colours would diverge between boards.
